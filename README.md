# RUBY Analyzer（独立版）

SillyTavern 1.16+ 的独立第三方扩展。基于对话楼层周期性调用 AI 执行角色分析任务，将结果写入聊天世界书。

完全脱离宿主插件运行，仅使用 SillyTavern 官方扩展 API（`SillyTavern.getContext()`）、原生 STscript 命令与原生事件系统。

## 功能

- **无感后台监听**：基于酒馆原生事件（`GENERATION_ENDED` / `CHAT_CHANGED` / `MESSAGE_RECEIVED`），每条 AI 回复后自动判断周期位置，到点静默执行分析，不占用前台、不打断对话
- **周期调度**：周期位置 = `((AI回复楼层 - 1) % 周期长度) + 1`，纯函数现算；漏触发的楼层自动累积补齐；支持同位置多任务按序独立执行
- **增量阅读**：每个任务独立维护"已读书签"（聊天元数据），只读上次之后的新楼层（含被隐藏正文），每次最多 20 楼；单次正文上限 **20 万字符**，超出部分后续剩余正文直接抛弃（上限只作用于对话正文，参考条目与分析输出引用完整保留，绝不因截断丢失）
- **总结接口（小白x / SP·数据库 / 柚月记忆表）**：玩家面板"总结接口"页签可启用小白x剧情总结、SP·数据库 表格总结或 yuzuki-Memory 记忆表总结——分析时已总结楼层用其总结内容替代原文注入，总结边界之后的新楼层照常读取原文；周期位置、楼层计数、任务书签计算完全不受影响；未安装或无数据时自动回退纯原文模式。小白x 读聊天元数据里的结构化总结（事件/人物事实/剧情阶段）；SP·数据库 读其写入世界书的可读条目（总结表/重要人物/剧情大纲，按消息上的 TavernDB 表格快照判定边界）；柚月记忆表 读聊天元数据 `yuzukiMemory` 的记忆总结表（总结标题/核心角色/楼层数/总结内容/未解决问题，按各记录楼层区间并集的连续链判定边界，楼层有空洞时边界停在空洞前防误替换，剧情摘要时间线可一并注入、可在面板关闭）——均只读、零模块耦合、不修改插件数据；随配置模板导出/导入
- **导演模式（创作者版面·任务页翻转进入）**：任务配置页顶部的「🎬 导演模式」按钮翻转入独立界面。开启导演周期后，Ruby 作为导演在本周期位置1（启用后下一两条AI回复）运行一次，根据正文发展、任务优先级（数字越大越优先）、近5周期唤醒记录与久未触发统计，为本周期排出「位置→任务」调度表——调度表经严格两级解析（任务id为主、任务名回退），格式错乱/不完整按创作者设定的次数自动重试，重试耗尽弹红色警告、本周期空转可手动重跑；此后每到计划位置自动唤醒对应任务（沿用其完整分析管线与书签，到点即跑、忽略关键词扫描），每任务每周期至多一次，最低任务间隔可硬性约束（0=由AI决定）。创作者可控：周期长短、最低间隔、重试次数、参考条目勾选（导演专属读取）、每任务优先级数字与可选简介（留空自动从提示词条目捕捉约200字切面）；**排期密度指导**内置于提示词——任务数量应贴近创作者设置的最低间隔（如20楼间隔2≈9个），未设间隔时按2~3楼一个估算（20楼约7~10个），避免长周期排得过稀；**导演API**为RUBY API的复制（可单独为导演换模型，留空字段跟随RUBY API，流式等传输方式完全跟随RUBY基础API设置）；**激进模式**下导演额外输出"下次导演间隔"自决下一次出现时间（不受固定周期约束）；两种模式均注入**迭代学习**——上周期计划数/实际触发数/玩家手动执行次数作为排期参考；选用 gemini 3.5 及以上模型（含pro/flash）时自动把破限预填充的assistant消息改为user（谷歌已取消预填充支持）；调度计划写入聊天世界书关闭条目仅供引擎读取，每项配置带 ? 帮助弹窗；停用即恢复静态位置调度，书签与数据不丢
- **参考条目池 / 任务输出引用**：世界书条目注册为变量注入提示词；任务间可互相引用输出（含引用自己的上次结果实现跨周期累积）。插件内置**约束库**参考条目（反八股检查标准，源自《县城》卡 14_约束库.yaml）：所有任务的参考勾选中直接可用、新建任务默认勾选；若创作者的世界书存在同名"约束库"条目，内置勾选项自动隐藏、勾选与运行时解析都改用创作者的条目（运行时世界书优先，无需加入参考池）
- **写卡模式（第三页签）**：内置 Ruby 写卡全流程（Step0 美学思考 → Step8 分析提示词，含可选 Step4 NSFW / Step6.5 交接 / StepX 自检）。规则与人设以深度 0、排序 999 常驻强调注入，步骤指令按当前步骤注入聊天附加世界书；创作者用自己的预设/API 原生对话，RUBY 只监听——检测到每步的 yaml 完成标记后自动把产物写入《ruby写卡初稿》世界书（角色内容按顺序排角色后、世界/NPC/速览排角色前、分析提示词进关闭条目并自动填角色名关键词），并自动切换下一步骤；**人物型草稿按人物分条目**：Step3 角色卡 / Step4 NSFW档案 / Step5 NPC（每 NPC 或分组独立条目）/ Step8 分析提示词均按人物身份存为独立条目，同名人物重跑→更新原条目，不同人物（名字相似度低）→另存新条目，支持反复添加新人物互不覆盖；步骤说明同步在悬浮球旁气泡弹出；进度存聊天元数据，换聊天不串进度
- **悬浮球 + 完整面板**：可拖动悬浮球（角色头像圆形裁切 + 底部状态徽章：绿√=监听中 / 蓝点脉冲=分析中 / 红×=错误 / 灰点=待机 / 紫✎=写卡会话）一键打开配置面板；酒馆扩展设置栏提供悬浮球显示开关与大小拉条（60px 最大、可逐步缩小），也可用 `/ruby` 命令打开面板
- **卡片中心配置（无全局任务）**：任务配置通过酒馆官方 `writeExtensionField` API 写入角色卡的 `data.extensions` 字段，**导出/分享角色卡时配置随卡携带**，其他环境导入即自动生效；打开角色卡后导入模板或新建/修改任务会**自动绑定到当前卡**；引擎只执行已绑定角色卡的配置，未打开卡/未绑定时面板提醒绑定（任务级角色限定已移除——配置随卡生效，无需重复指定）
- **API 安全**：密钥只存于本机扩展设置，绝不进入角色卡 / 世界书 / 导出模板；自定义端点请求经酒馆服务端转发（无 CORS、密钥不暴露前端）
- **多配置方案 + 模板导入导出**：多套方案随时切换；JSON 模板即插即拔，兼容旧版模板格式
- **原生更新通道**：manifest 已启用 `auto_update`，通过酒馆扩展管理器自动/手动更新

## API 渠道

所有分析调用均走酒馆通道（由酒馆前端服务发起、酒馆服务端转发出站），不存在任何浏览器对外的独立直连；全过程异步执行，不阻塞对话。

| 渠道 | 通道 | 说明 |
|---|---|---|
| 酒馆主 API | 原生 `generateRaw`（quiet 调用） | 仅借用酒馆主通道发送：**绕过预设的提示词注入**——主提示词、越狱、角色卡、聊天记录一概不进入上下文，发送的只有 RUBY 自己组装的破限消息与任务提示词（与酒馆自身静默提示词同一机制）；RUBY 生成参数通过官方 `CHAT_COMPLETION_SETTINGS_READY` 事件钩子覆写到本次请求。出站请求与普通生成同源同形 |
| 自定义 OpenAI 兼容端点 | 原生 `ChatCompletionService`（ST 1.16 官方请求服务） | 酒馆官方为扩展提供的 chat completion 请求服务：同一后端端点、同一负载组装约定、同一 SSE 解析器（`EventSourceStream` + `getStreamingReply`）。地址填到版本段（如 `https://api.deepseek.com/beta`），服务端自动拼接 `/chat/completions`；可一键拉取模型列表 |

### 模型名称：自由填写 + 快捷选择

主 API 与独立导演 API 的模型名称均为**输入框常驻、可自由填写**（拉取列表前后都可直接手输任意模型名，覆盖中转站的自定义模型、`model:deepseek/chat` 之类的带前缀写法等）。点击「连接/拉取模型」后出现的下拉只作快捷选择：选中即回填输入框并保存；头部占位项「— 从列表选择 / 输入框自由填写 —」不动输入框已填的自定义值，不在列表中的填写值在重新拉取后也会保留。保存与运行一律以输入框的值为准。

## 消息内 HTML 接口之二：/ruby run（手动分析触发）

玩家面板「手动执行分析」区带**纯手动分析**开关：开启后点击按钮走独立手动流（独立书签 `manual:task_N`、不计入导演迭代统计），与周期/导演两条自动逻辑互不干扰；关闭则保持原有补充模式（与自动流共享阅读进度并推进书签）。开关状态存于本机 UI 偏好。`/ruby run` 斜杠命令保持补充模式，不受开关影响。

HTML 按钮的**动作通道**：触发一个或多个分析任务手动执行，`await` 到分析完成（AI 生成 + 输出写入聊天世界书）才返回——返回后立刻 `/ruby read` 即可拿到新数据重渲染面板，玩家看到的就是"点按钮 → 状态栏更新"。

### 语法

```
/ruby run task=<spec>[,<spec>...] [json=true]
/ruby run all=true [json=true]
```

| 参数 | 说明 |
|---|---|
| `task=` 的 spec | 任务 id（`1`）/ 任务名（`沛霖内心`）/ promptKey / outputKey / 捕捉关键词——前端只知道条目关键词也能精确落点；逗号分隔批量执行 |
| `json=true` | 返回结构化 JSON；默认返回文本摘要 |
| `all=true` | 全部启用任务 |

### 返回契约（json=true）

```json
{"ok":true,"summary":"沛霖内心, 沛霖生理 执行完毕（2/2 成功）","completed":2,"failed":0,
 "tasks":[{"name":"沛霖内心","ok":true,"outputKey":"沛霖内心"}]}
```

`tasks[].outputKey` 是本次更新的世界书条目键——前端逐个 `/ruby read key=<outputKey> json=true` 刷新对应卡片。任务失败时该条 `ok:false` 带 `reason`；引擎正忙返回错误文本（`RUBY error: 已有分析任务正在执行中…`），前端 parse 失败要兜底显示。

### HTML 端组合范式（按钮 → 分析 → 刷新）

```js
async function analyzeAndRefresh(specs, rerender) {
    const out = await runSlash(`/ruby run task=${specs} json=true`);
    let result;
    try { result = JSON.parse(out); } catch { return showError(out); } // 忙/未绑定等错误文本
    if (!result.ok) return showError(result.summary);
    for (const t of result.tasks.filter((t) => t.ok && t.outputKey)) {
        await rerender(t.outputKey);   // 内部 /ruby read + 自行渲染
    }
}
// 按钮: <button onclick="analyzeAndRefresh('沛霖内心,沛霖生理', rerenderCard)">手动分析</button>
```

与 `/ruby read` 组合即完整闭环：`read`（读）+ `run`（写）。渲染成状态栏、图鉴、进度条还是别的什么，全由前端决定——接口不预设格式。

## 消息内 HTML 数据接口：/ruby read

给消息内 HTML 前端（``` 围栏 → iframe 通道，可调宿主斜杠执行器）提供的**只读数据通道**。HTML 由此可以读取 RUBY 写入世界书的任何内容（分析输出、写卡记录、设定条目），自行做特征识别与渲染——渲染成什么由前端自己决定，本接口不预设任何格式。

### 语法

```
/ruby read <关键词> [key=同前] [json=true] [all=true] [book=chat|char] [raw=true]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `<关键词>` / `key=` | 空 | 检索词。精确命中（条目关键词数组含逗号拆分逐一比对）优先；无精确命中取包含式模糊命中的第一条 |
| `json=true` | 关 | 返回结构化 JSON 记录；默认返回纯文本 content |
| `all=true` | 关 | 返回全部命中（JSON 数组）；无关键词 + all = 整本书导出（含 disabled 条目） |
| `book=chat` | chat | `chat`=聊天世界书（RUBY 分析输出所在）；`char`=角色（主）世界书（设定/参考条目所在）；**任意书名**=全局导入的世界书（无需绑定，书不存在返回空） |
| `raw=true` | 关 | 保留 `{{user}}` 等宏原文；默认 content 经宏替换后返回 |

### 返回契约（json=true）

单条：`{"uid":12,"book":"ruby-角色名·剧情分析","keys":["沛霖内心","沛霖"],"comment":"…","content":"…","disabled":false,"constant":false}`
全部（all=true）：同结构数组；无命中：`[]`（合法 JSON）；执行异常：文本 `read failed: …`（前端需兜底 parse 失败）。

### 特性

- **零副作用**：纯读。不创建书、不写条目、不改状态；`loadWorldInfo` 解析真实 uid，不触发宿主 toastr
- **未绑定探测**：聊天未绑定书时，按 RUBY 输出书命名规则（`ruby-<角色名>·剧情分析`）探测已存在的书，找不到返回空
- **disabled 可读**：被停用的条目照常返回（`disabled` 字段标注），写卡记录/历史分析都能取

### HTML 端调用范式（任何前端通用）

```js
async function runSlash(command) {
    if (typeof STscript === 'function') return String((await STscript(command))?.pipe ?? '');
    if (typeof executeSlashCommands === 'function') return String((await executeSlashCommands(command))?.pipe ?? '');
    if (typeof triggerSlash === 'function') return String((await triggerSlash(command))?.pipe ?? '');
    throw new Error('宿主未提供斜杠执行接口');
}
// 例：拉取沛霖的内心分析（JSON），自行识别字段并渲染
const raw = await runSlash('/ruby read key="沛霖内心" json=true');
const rec = JSON.parse(raw);           // 失败时 raw 是错误文本——先 try/catch
const fields = parseMyYaml(rec.content); // 解析方式由前端自定（宽松抓 "k: v" 行即可）
renderMyOwn(rec, fields);              // 怎么渲染、识别什么特征，全是前端的事
```

触发方式照项目惯例：卡内正则字面捕捉标记（如 `【状态面板】`，placement `[1,2]` = 用户输入+AI 输出，markdownOnly）替换为你的 HTML 文件（文件首尾 ``` 围栏，内部脚本经 iframe 通道执行）。

## 写卡模式（第三页签 ✍️）

把「通用分析器/RUBY条目」的写卡流程内置进插件，**走酒馆原生通道**：创作者用自己的预设和 API 与 Ruby 对话，RUBY 只监听、不代发消息。

- **开始会话**：在任意聊天点"开始写卡会话"，RUBY 在聊天附加世界书注入 Ruby 人设 + 步骤规则（深度 0、排序 999 常驻强调）与当前步骤指令（含可选的步骤说明条目）
- **快速/对话双模式**：快速模式 = 检测到完成标记自动切换（默认）；对话模式 = 切换前弹确认框，可选"我还想聊聊"注入"创作者不完全满意、继续讨论勿下结论"的临时条目（下一阶段切换时自动清除），支持长期纠正 Ruby
- **严格完成识别**：Step0-4 的 yaml 总结需包含必需字段（如 Step1 需"人生经历+内在张力"、Step3 需"character+角色核心+写作基准"）才算完成，Ruby 展示的草稿片段不会误触发切换
- **自动清理冗杂**：进入 Step4 自动删除 Step1/2 的注入条目与草稿；进入 Step8 删除 Step7；Step6.5 已移除（遗留自动清）；总览收尾后只保留美学/角色/NSFW 设定与分析提示词草稿，其余 RUBY 条目全部清除
- **总览收尾（🏁 手动进入）**：全部完成后点击"总览"，Ruby 输出含「玩家已完成」的 yaml 后自动执行最终清理并结束会话
- **草稿写入《ruby写卡初稿》**：角色内容（Step0-4）按步骤顺序排在角色后（order 100+）；NPC 设定、人物速览、创作交接排在角色前；分析提示词放入**关闭条目**（order 200+），并按 `<角色名_分析类型>` 标签自动填角色名关键词；人物速览关键词填"人物速览"+ 人物名
- **步骤说明气泡**：切换步骤时悬浮球旁弹出对应说明（可关闭，60 秒自动收起），也可在选项里关闭注入
- **进度记忆**：步骤进度存于聊天元数据，重开聊天自动恢复；换聊天互不干扰
- **历史合成清单自动补扫**：合成清单不只在"新回复"里生效——会话开始或重开聊天恢复进度时，自动扫描聊天历史里未处理的 `<ruby合成>` 清单，发现即弹窗询问是否现在下载（选过"再改改"的楼层不会重复打扰，合成失败的可重试）；也可 `/ruby cw action=compose` 随时手动触发
- **特殊步骤：合成角色卡-主世界书 / 合成角色卡-聊天世界书（仅手动进入）**：已经有一本世界书、只想让 Ruby 认识它再重建？在写卡面板"特殊步骤"区手动点击进入——RUBY 用代码清点对应世界书的全部条目（uid、条目名、关键词、副关键词、位置、深度、顺序、灯位、选择性、触发概率、内容长度与预览），写入常驻注入的【世界书现状】知识条目；Ruby 以此为唯一权威认知汇报清点、讨论合成策略，然后输出含既有条目引用的合成清单——`{"书": "主世界书", "uid": 5}` 或 `"主世界书:5"` / `"聊天世界书:12"`，**也支持任意书名**（`{"书": "导入的书名", "uid": N}` 或 `"书名:N"`，全局导入的书无需绑定聊天/角色），条目字段（条目名/关键词/位置/顺序/深度/灯位/副关键词/启用）省略=完全沿用现状、填写=覆盖进卡；实际 uid 可用 `/ruby read all=true json=true book=书名` 查询；记录编号引用与 uid 引用可混用，"角色描述来源/开场白来源"同样支持。主世界书只读不改动，聊天世界书引用条目按覆盖字段同步整理；重新点击步骤卡即刷新清点（uid 以最新清点为准）；RUBY 流程条目（规则/路线图等）自动标注禁止引用；切换标记不能进入特殊步骤（防 AI 自作主张）
- **手动合成按钮**：写卡控制台「📦 手动合成」——立即检查当前楼层（及聊天历史）里的 `<ruby合成>` 清单，找到就弹窗确认下载；配合特殊步骤可实现"已有世界书 → 清点 → 清单 → 一键出卡"的全流程
- **结束会话**：草稿保留在《ruby写卡初稿》可随时打开检查；"结束并清空"会删除 RUBY 创建的全部写卡条目
- 写卡数据由 `tools/build-cardwriter-data.mjs` 从「RUBY条目」源目录生成，更新文案后重跑脚本即可

## 配置层级（卡片中心模型）

RUBY 的任务配置**只随角色卡存在**，保存于角色卡 JSON 的 `data.extensions.RubyAnalyzer` 字段：

- 打开角色卡后，导入模板、新建或修改任务会**自动写入当前角色卡**（首次保存即自动绑定）
- 引擎只运行**已绑定角色卡**的配置；未绑定时待机，并在主面板/绑定页提示绑定
- 未打开角色卡时配置暂存于 `extensionSettings.RubyAnalyzer.global`（本机全局层，不随卡导出），面板会提醒打开角色卡
- 旧版本地绑定（`characterConfigs`）自动兼容读取，保存修改时自动迁移进角色卡
- API 凭据（`api`）与界面偏好（`ui`）始终只存本机 settings.json，绝不进入角色卡

## 与旧版（宿主插件内嵌版）的差异

- 触发机制由宿主插件回调改为酒馆原生事件，行为等价且更可靠
- API 调用改为 `generateRaw`（主 API）或酒馆后端代理（自定义端点），大提示词不再经过命令行解析
- 宿主插件的剧情总结集成不再存在；如需历史背景参考，将总结条目加入参考池即可
- 无感更新交由酒馆扩展管理器的官方更新通道
- 配置存储从宿主任务系统迁移为独立的角色绑定 / 全局两层结构；旧版导出的 JSON 模板可直接导入

## 配置模板（热插拔）

导入页兼容三代模板格式，旧版导出的 JSON 可直接导入：

| 来源 | 识别特征 | 导入行为 |
|---|---|---|
| 本插件 v3 | `_meta.version: 3.0.0`，presets 数组含 `cyclePositions`/`keywordScan`/`characters` | 全字段保真往返 |
| 旧版 v2.x（多方案） | `_meta.type: RUBY_ANALYZER_PRESET` + `presets` 数组，任务仅 `triggerFloor` | 每方案独立导入；`triggerFloor` 自动转为周期位置；`startupTask.triggerFloors` 同步转换；`gen`/`jailbreak`/标签一并导入 |
| 旧版 v1.x（单方案） | 无 `presets`，顶层 `tasks`/`referencePool`/`startupTask` | 包装为名为"导入的方案"的单方案导入 |

导入前会显示来源版本与方案/任务数量并要求确认；导入后 `/ruby reload` 生效。反向兼容：本插件导出的模板同样可被旧版导入（多位置任务退化为首个位置）。

## 安全说明

- API 密钥仅保存在 `settings.json` 的扩展设置中，导出模板、角色卡、世界书均不含密钥
- 角色卡绑定只写入任务配置数据（方案/任务/参考池/破限/生成参数）到 `data.extensions.RubyAnalyzer`，不包含 API 凭据
- 全部请求经由酒馆官方请求服务发出，由酒馆服务端转发，出站请求与正常酒馆生成同形（无独立客户端特征）；浏览器端不存在对模型服务商的直接调用
- 面板密钥输入框为密码类型，不在界面明文展示
